1. Executive Summary

This Technical Specification Document provides a comprehensive blueprint for migrating the Procurement P&L Intelligence Dashboard from a single-file HTML artifact into a production-ready, full-stack web application backed by Supabase (PostgreSQL).

The dashboard currently covers:

  • Multi-division procurement P&L tracking — SMM, SUN, OliveLink, Combine
  • Actual vs Budget comparison across 15 cost components per period (Q1–Q4, FY, YTD)
  • ROI, Value Creation, Net Value Creation, and SUM analysis with Hackett benchmarks
  • BI JISDOR FX rate integration with live refresh (USD ↔ IDR)
  • BCG-style dual Actual/Budget charts with CAGR overlays and value labels
  • YoY comparison, Peer Parity Engine, and Ratio to Revenue/GP analysis
  • P&L + ROI Report (formatted table: cyan Net Value Creation, orange SUM rows)
  • User Directory with role-based access (Admin / Manager / Viewer)
  • AI Assistant (Claude Sonnet — context-aware P&L analysis)
  • Export to Excel (.xlsx), PDF, and PowerPoint (.pptx) with embedded charts
PROPOSED STACK
Next.js 14 (App Router) · Supabase (PostgreSQL + Auth + Storage + Realtime) · TypeScript 5 · Zustand · TanStack Query · TailwindCSS · Chart.js 4 · jsPDF · pptxgenjs · xlsx-js-style

2. Database Schema (ERD / Table Structure)

All tables are hosted in Supabase (PostgreSQL 15). UUIDs are used for all primary keys. Row-Level Security (RLS) policies are applied at the database level to enforce access control independently of the application layer.

2.1  users

Extends auth.users. Stores application-level profile, role, and division access configuration.

ColumnTypeConstraintDescription
idUUIDPK, FK → auth.usersSupabase auth user ID
emailVARCHAR(255)NOT NULL, UNIQUEWork email address
full_nameVARCHAR(255)NOT NULLDisplay name
roleENUMNOT NULL, DEFAULT 'viewer'admin | manager | viewer
division_accessTEXT[]DEFAULT '{}'Specific divisions the viewer can read
is_activeBOOLEANDEFAULT trueSoft-disable without deleting the row
invited_byUUIDFK → users.id, NULLAdmin who granted access
created_atTIMESTAMPTZDEFAULT now()Account creation timestamp
updated_atTIMESTAMPTZDEFAULT now()Last profile update

2.2  divisions

Master list of procurement divisions. "Combine" is a virtual division computed at query time — it is NOT stored as rows.

ColumnTypeConstraintDescription

2.3  periods

Master calendar of reporting periods. FY rows are aggregate markers; YTD rows carry a ytd_through_q flag.

ColumnTypeConstraintDescription

2.4  pnl_data (Core Fact Table)

One row per division × period × record_type. This is the primary source for all P&L calculations. net_value_creation and roi_pct are PostgreSQL generated columns — always consistent.

ColumnTypeConstraintDescription
idUUIDPK
division_idUUIDFK → divisions.id, NOT NULLDivision reference
period_idUUIDFK → periods.id, NOT NULLPeriod reference
record_typeENUMNOT NULL'actual' | 'budget'
cost_savingNUMERIC(12,4)DEFAULT 0USD Million
cost_avoidanceNUMERIC(12,4)DEFAULT 0USD Million
total_value_creationNUMERIC(12,4)DEFAULT 0cost_saving + cost_avoidance
initial_sumNUMERIC(12,4)DEFAULT 0Spend before saving (USD Mn)
sum_after_savingNUMERIC(12,4)DEFAULT 0Spend after saving
total_cost_incurredNUMERIC(12,4)DEFAULT 0Sum of 15 cost components
net_value_creationNUMERIC(12,4)GENERATEDtotal_value_creation − total_cost_incurred
roi_pctNUMERIC(8,4)GENERATEDnet_value_creation / total_cost_incurred × 100
value_to_sum_pctNUMERIC(8,4)GENERATEDtotal_value_creation / initial_sum × 100
revenueNUMERIC(14,4)DEFAULT 0Division revenue (USD Mn)
gross_profitNUMERIC(14,4)DEFAULT 0Division GP (USD Mn)
uploaded_byUUIDFK → users.idWho loaded this data
source_fileVARCHAR(500)NULLOriginal filename reference
created_atTIMESTAMPTZDEFAULT now()
updated_atTIMESTAMPTZDEFAULT now()
UNIQUE KEY
UNIQUE constraint on (division_id, period_id, record_type) — prevents duplicate entries. Upload uses an UPSERT (INSERT … ON CONFLICT DO UPDATE) pattern.

3. Data Flow Requirements (CRUD API)

The application uses Supabase's auto-generated REST API (PostgREST) for standard CRUD operations, supplemented by Next.js API Route Handlers for complex operations — file parsing, AI proxying, and export generation. All endpoints require a valid Supabase JWT in the Authorization: Bearer <token> header.

4. Authentication & Access Control (RBAC)

Authentication is handled by Supabase Auth (email/password + magic link). Authorization is enforced at two independent layers: PostgreSQL Row-Level Security (RLS) and Next.js middleware route guards.
